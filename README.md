# UNSHAKEN — automated Stoic content channel

Generated content pipeline: a verified quote library, a visual template, a daily
selector, a voice-alignment pipeline, and a posting watchdog.

**Start here: `SETUP.md`** — step-by-step instructions to push this to GitHub
and turn it on.

# Visual template (placeholder name: UNSHAKEN)

`render.py` turns one library item into:
- Reel / Short / TikTok, 1080x1920 MP4: 2.2 s hook, then the text highlighted word by word (spoken = ivory, current = bronze, upcoming = dim), slow background zoom, source credit always visible.
- Post 1080x1350 (4:5) and Story 1080x1920 stills.

Long passages are split into pages automatically (about 55 words per page, cut at sentence ends when possible).

## Files
- brand.json: colors, fonts, safe zones, timing. Change the name and handle here once confirmed.
- kit.json: hooks (with author and theme constraints), CTAs, hashtags, caption template.
- fonts/: Lora + Poppins (free OFL fonts) so the template runs anywhere, including GitHub Actions.

## Usage
    import render as R
    R.render_still(item, "post", "post.jpg")
    R.build_reel(item, "reel.mp4", hook=hook_text, audio="a.mp3", timings=[(start, end), ...])

Without audio/timings it uses a silent track and estimated timing (2.3 words/s). That is what the previews show.

## Still stand-ins
- Background is procedural dark stone. In production make_bg is replaced by a Pexels photo plus a 55% black overlay.
- Audio and per-word timing come from LibriVox + forced alignment (next step).

## Audio (added)
- `audio/audio_sources.json`: which public-domain LibriVox recordings match which text (only the SAME translation is allowed).
- `audio/prepare_audio.py`: `resolve` -> `matrix` -> `transcribe` (faster-whisper) -> `align` (match each item in the transcript, cut, loudness-normalise, write per-word timings). Run through `.github/workflows/audio.yml`.
- `audio/align.py`: the matcher (tested offline on simulated transcripts: 115 of 116 Meditations items located, mean start error 0.05 s).
- `music.py` + `music/`: three ambient beds generated by code, so there are no licenses or Content ID claims. The reel builder ducks them under the voice.
- `audio/record_script.md`: the items that have no public-domain recording, ready to be read by a person.
- `render.build_reel(item, out, hook=..., timings=..., audio=clip, music=bed)`.

## Monitor / watchdog (added)
- `watchdog.py`: runs every 30 minutes (`.github/workflows/watchdog.yml`, cron is always UTC). For each of today's slots (from `schedule.json`, times in America/New_York via `zoneinfo` - no manual DST edits, ever), once the slot's time has passed it publishes whatever platform hasn't succeeded yet. A slot still unposted after 2.5 hours makes the job exit non-zero, which is what triggers GitHub's automatic failure email to the repo owner - the "monitor every half hour, re-post whatever is late" rule from the original doc.
- `publish.py`: one stub function per platform. Each just raises `NotConnected` until that platform's secrets exist - so linking an account later means filling in one function, nothing else in the pipeline changes.
- `publish_log.json`: append-only record of every publish attempt (committed by the workflow), so nothing is ever double-posted.
- `run_day.py`: generates a day's plan (calls `selector.py`), phased per `AUDIO_PHASE_1_DAYS` in `selector.py`.
